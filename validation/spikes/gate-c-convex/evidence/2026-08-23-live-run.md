## What the harness proved

- Two independent clients maintained subscriptions and each published an event;
  both observed the shared state reach the same revision and event count.
- Two concurrent mutations with one stable event ID committed one accepted effect
  and one duplicate response. The scoped revision advanced once.
- A 1,000-path manifest remained absent from the current projection while nine of
  ten chunks existed. Early completion failed. Completing the tenth 100-path
  chunk atomically selected the revision and advanced context revision once.
- The mutation boundary rejected an eleventh chunk and a 101-path chunk. The
  accepted fixture used ten calls whose largest JSON-encoded argument was 3,050
  bytes, avoiding a single large mutation.
- Vector search used `scopeKey` as an indexed equality filter, then reloaded the
  vector and semantic object and checked active state, project, repository,
  scope, content revision, and model version.
- A same-vector record in another project/repository was not returned. Supplying
  authorization for a different project/repository after searching the first
  scope returned no records.
- A newly inserted vector was returned by the immediately following action.
  Updating an object removed its prior vector, installed exactly one vector for
  the new content/model revision, rejected a stale write, and deletion removed it
  from retrieval.
- A forced context-revision change on both attempts returned a labeled structural
  fallback after two bounded retries.
- Time-based cleanup and explicit scope deletion each removed semantic objects,
  vectors, findings, and context-delivery receipts.
